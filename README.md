# 园区光纤环网 · 拓扑工作台

改造前找出**单条链路断开即隔离站点的薄弱段（桥 / bridge）**，再通过**试接一条虚拟备纤**
验证风险是否真正消除，并支持**批量方案筛选**与**有序备纤计划复核**（同一座桥只归最早
覆盖的步骤）。React + TypeScript 单页工作台，Vitest 用**删边预言机**对随机小图做
差分核对，Tarjan 桥算法在上限（200 000 站点 / 400 000 链路）下 5 秒内完成且全程迭代、不递归。

---

## 1. 输入契约

页面接受粘贴或上传一个 **JSON 对象**，仅使用普通 JSON 基础类型（对象、数组、字符串、数字、
布尔、null）。结构：

```json
{
  "sites": ["S1", "S2", "S3"],
  "links": [
    { "id": "L1", "u": "S1", "v": "S2" },
    { "id": "L2", "u": "S2", "v": "S3" }
  ]
}
```

| 字段 | 规则 |
| --- | --- |
| `sites` | **2–200 000** 个站点；编号**唯一、非空**。编号写为字符串；整数数字也会按其十进制文本接受（如 `7` 与 `"7"` 等同）。 |
| `links` | **0–400 000** 条无向链路；链路编号**唯一、非空**。 |
| `links[].u / v` | 端点编号**必须存在于 `sites`**；**禁止自环**（`u === v`）。 |
| 平行链路 | **合法**：同一对站点之间允许存在多条不同编号链路，它们彼此构成热备，均不算桥。 |
| 连通性 | **原图必须连通**（孤立站点 / 多分区将被拒绝）。 |

布尔、`null`、对象、数组、空串、`NaN`/`Infinity` 均不能作为编号。

> 编号的“字节序”按其 **UTF-8 编码字节**逐字节比较（等价于 JS 字符串默认字典序，
> 实现与测试均有说明和差分验证）。注意这是字节序而非数值大小：`L10 < L2`。

### 输出语义（基线）

* 按**链路编号 UTF-8 字节序**列出**全部脆弱链路（桥）**；
* 每条给出**断开后两个连通块中较小者的站点数**（`min(子树, n − 子树)`）；
* **不输出任何站点清单**（表格仅展示编号、端点与较小侧站点数，供核对）。

### 试接（虚拟备纤）

从**现有站点**中选择**两个不同端点**试接一条虚拟备纤：

* 页面**独立**给出试接后 **仍脆弱** 的链路，以及相对基线 **已消除** 的链路；
* 试接**不改写基线**：基线对象在导入时固定，试接只读取并派生新结果；
* **非法导入**保留上次有效拓扑并显示明确错误；**非法试接**保留上次试接结果并显示明确错误。

一条新边 `(a,b)` 恰好消除桥树中 `a↔b` 路径上的全部桥——长链、大环、平行链路均得到
精确且稳定的结论（由随机差分测试锁定）。

### 批量方案筛选

在第 4 区粘贴 **1–100000 项**的 JSON 数组，每项为**仅含** `a`、`b` 两个字段的对象
（站点编号规则同单次试接）：

```json
[{"a": "S1", "b": "S9"}, {"a": "S2", "b": "S7"}]
```

* 整批先校验结构、字段、端点存在且互异；**任一项非法都按下标（0 起）报错**，
  保留上次批量结果，且不改写基线与单次试接结果；
* 全批校验通过后一次性生成结果并整体替换：按**输入下标**分页显示端点对及其
  **可消除的基线桥数量**（不展开链路清单），重复候选按原序保留；
* 空批次、额外字段、超过 100000 项均整体拒绝；
* 合法新拓扑导入后旧批量结果清空；非法导入保留既有结果。

批量计数不循环调用单次试接：Analyzer 在合法导入时基于 Tarjan 父树与桥标记构建
**只读桥前缀 + 二进制提升（binary lifting）索引**，每项经最近公共祖先（LCA）以
`prefix[a] + prefix[b] − 2·prefix[lca]` 计数，单项 O(log n)，全程迭代不递归。

### 有序备纤计划复核

在第 5 区粘贴 **1–100000 项**的 JSON 数组（契约与批量方案相同，每项仅含 `a`、`b`），
**数组顺序即敷设顺序**：

```json
[{"a": "S1", "b": "S9"}, {"a": "S2", "b": "S7"}]
```

* 页面按顺序分页显示每步的**端点对、本步首次消除的基线桥清单**（按链路编号
  UTF-8 字节序）、**边际数、累计数与剩余数**；
* 同一座基线桥**只归最早覆盖它的步骤**：重复、反向、交叠或被包含路径的后续步骤
  边际数可为零；各步清单**互斥**，其并集恰为整个计划覆盖的基线桥；
* 计划输入框为**独立草稿**，上次成功结果独立保存；空数组、超限、额外字段、
  端点不存在或相同均**整批拒绝**并指出**零起下标**，不产生部分结果，
  也不改变基线、单次试接与批量筛选结果；
* 合法新拓扑导入后旧计划结果清空；非法导入继续保留。

计划复核不逐步调用单次试接、不逐路径扫描：全批校验通过后，Analyzer 复用 DFS 父树
与只读 LCA 索引，并用一个**向父级跳转的并查集**维护尚未归属的桥边——非桥树边
预先并入父级跳过；每步从路径两端跳至 LCA，途经的未归属桥首次归属本步并立即
压缩到父级。每条桥全程只归属一次，计算完成才原子替换展示。

## 2. 本地开发

```bash
npm ci
npm run dev        # 开发服务器（Vite，默认 5173）
npm run build      # 类型检查 + 生产构建到 dist/
npm run preview    # 本地预览生产构建
npm run test       # Vitest 全量测试（含删边预言机差分）
npm run typecheck  # 仅类型检查
npx tsx src/core/perf.ts   # 上限数据（200k/400k）性能基准，断言 < 5000ms
```

测试构成：

* `src/core/utf8.test.ts` — UTF-8 字节序与真实 `TextEncoder` 编码的差分；
* `src/core/parse.test.ts` — 输入契约的各类合法 / 非法情形；
* `src/core/analysis.test.ts` — 生产 Tarjan 与**删边预言机**在随机小图上的逐项核对
  （桥集合、较小侧站点数、试接后仍脆弱 / 已消除），以及长链、大环、平行链路、蝴蝶结等典型拓扑；
* `src/core/batch.test.ts` — 批量方案筛选：随机连通多重小图上每项计数与
  `trial(a,b).removed.length` 及删边预言机一致、末项非法无部分结果、
  契约（空批次 / 额外字段 / 超限 / 下标报错）与较深图的 LCA 差分；
* `src/core/plan.test.ts` — 有序备纤计划：随机连通多重小图上**按顺序合并单次试接
  结果作预言机**逐项核对（首次归属清单、边际 / 累计 / 剩余、互斥性与并集），
  覆盖顺序归属（重复 / 反向 / 交叠 / 包含）与末项非法整批拒绝，以及 200 000 站点
  长链“首步全覆盖 + 99999 条子路径均为零”的极限形态；
* `src/ui/App.test.tsx` — 导入→基线→试接→批量筛选→有序计划→非法操作保留上次结果的端到端交互。

> 所有结论均由当前输入实时计算，**不存在固定结果 / 固定答案**。

## 3. Docker Compose

### 发布页面（`web`，长期运行）

宿主机端口用可覆盖的 **`WEB_PORT`** 控制（默认 `8080`）：

```bash
docker compose up --build web                 # 默认 http://localhost:8080
WEB_PORT=9000 docker compose up --build web   # 覆盖为 9000
# 或复制 .env.example 为 .env 后修改 WEB_PORT
```

镜像为多阶段构建：Node 构建静态资源后，用零依赖 Node HTTP 服务器发布（带 SPA 回退）。

### 一次性验收（`verify`）

`verify` 是**一次性服务**：依次执行类型检查、Vitest 全量测试、上限 5 秒性能基准，
**全部通过则以退出码 0 结束**，不发布端口、不重启：

```bash
docker compose --profile verify build verify
docker compose --profile verify run --rm verify
```

## 4. 算法与工程要点

* **桥检测**：Tarjan 无向图桥算法，`low[v] > disc[parent]` 判桥；**平行链路通过“只跳过
  通向父顶点的同一条边”正确处理**（平行的另一条作为回边降低 low 值）。
* **较小侧站点数**：DFS 同时统计子树规模 `subtree[v]`，桥断开后两侧为 `subtree[v]` 与
  `n − subtree[v]`，取较小值。
* **试接消险**：桥缩点得到桥树；新边覆盖的恰为两端点在 DFS 树上的路径桥，用父边与深度
  求 LCA 路径，O(V) 派生。
* **批量方案筛选**：合法导入时基于 Tarjan 父树与桥标记一次构建**只读桥前缀 +
  二进制提升索引**（O(n log n)，200k 站点约 15 MB 类型化数组）；每项查询经迭代式
  LCA 以 `prefix[a] + prefix[b] − 2·prefix[lca]` 计数，O(log n)，不循环调用单次试接、
  不按链路数分配缓冲、不扫描链路集合。200000 站点长链 + 100000 组查询的构建与
  整批查询合计约 1 秒（见 `perf.ts`，预算 5 秒）。
* **有序备纤计划**：全批校验后复用同一 DFS 父树与只读 LCA 索引，以**向父级跳转的
  并查集**维护尚未归属的桥边——`find(v)` 返回 v 沿已归属 / 非桥边压缩后最近的、
  父边仍是未归属桥的祖先；非桥树边开工前预先并入父级。每步从路径两端跳至 LCA，
  途经的未归属桥首次归属本步并立即压缩到父级，每条桥全程只归属一次，总代价
  O((n + Σ首次覆盖数)·α(n) + 步数·log n)，不逐步调用 trial、不逐路径扫描。
  200000 站点长链“首步全覆盖 + 99999 条子路径”的构建与整批复核合计约 1 秒
  （见 `perf.ts`，预算 5 秒）。
* **不撑爆调用栈**：Tarjan 与连通性 / BFS 全部为**显式栈 / 显式队列迭代实现**，
  200 000 个站点的纯长链也不会递归（已实测）。
* **性能与内存**：邻接表、DFS 缓冲均使用紧凑类型化数组（`Int32Array` / `Uint8Array`），
  避免约 80 万邻接记录装箱；上限数据解析 + 基线 + 试接合计约 2 秒（见 `perf.ts`，预算 5 秒）。

## 目录结构

```
src/
  core/            纯逻辑（无 DOM 依赖，可独立测试）
    types.ts       数据类型与错误
    utf8.ts        UTF-8 字节序比较
    parse.ts       导入契约解析与校验（拓扑 + 批量方案 + 有序计划，含连通性）
    analysis.ts    Tarjan 桥分析器 + 试接 + 批量筛选 + 有序计划复核（迭代实现）
    oracle.ts      删边预言机（仅测试用朴素参考实现）
    *.test.ts      Vitest 差分 / 契约测试
    perf.ts        上限性能基准（含 200k 长链 + 100k 批量查询 + 100k 步有序计划）
  ui/              React 工作台（导入、基线复核、试接核对、批量方案筛选、有序备纤计划、分页表格）
docker/            零依赖静态服务器
Dockerfile         web 镜像
Dockerfile.verify  一次性验收镜像
docker-compose.yml web + verify(profile)
```
